# 学习方法

本文是学习区自身运转的指导：读什么、按什么顺序由 [learning-path.zh.md](learning-path.zh.md) 回答；本区各文件的入口与进度由 [index.zh.md](index.zh.md) 回答；本文只回答**学习过程该如何记录、笔记该如何组织**。本区的结构与约定仿照 deepseek-harness 仓库的 learning 区（那是这套方法的第一实例），并按 pi 仓库的现实裁剪。

## 宪法：与正式文档的关系

1. **事实不搬家**：工程事实的唯一归属（one home per fact）在事实源——根 [README.md](../README.md)、[AGENTS.md](../AGENTS.md)、[CONTRIBUTING.md](../CONTRIBUTING.md)、[packages/coding-agent/docs/](../packages/coding-agent/docs/index.md)（约 30 篇官方文档）、各包 package.json 与源码。本区笔记只链接、不复述；发现冲突时以事实源为准，并修本区对应内容。
2. **笔记拥有认知加工**：每篇笔记的增量价值必须落在事实源刻意不收的内容上——自己的因果链、误解与修正、实验观察。只复述事实、没有认知增量的笔记应当重写或删除。
3. **蒸馏出口**：当某篇笔记稳定、且暴露官方文档的真实缺口时，按 [CONTRIBUTING.md](../CONTRIBUTING.md) 的规则考虑改写进官方文档区。注意 pi 的贡献政策：新贡献者的 issue/PR 默认自动关闭、由维护者每日审阅——学习区不是贡献通道，蒸馏出口是「向维护者提案」或自用，不承诺回流。

## 版本对齐：随上游增量核对

本 fork 跟随上游 pi-mono 快速迭代（全部包 lockstep 同版本，patch 频繁）。因此学习区对标的**基准**应当显式化：初始基准 pi-coding-agent 0.85.1（commit 9767ba275，2026-09-07）。每次同步上游后做一次**版本对齐核对**，而非默认「已学内容自动失效」。

核对姿势（一次版本升级 = 三问）：

1. **改了哪些核心面**：diff 两个基准，只看触及已学/在学内容的实质代码变更，忽略文档、脚本、CI、merge 提交的噪声。
2. **有没有动摇已学结论**：逐条对照各阶段的过关标准，判断变更是「增量」还是「推翻」。
3. **增量落去哪**：新增的事实（新能力、新字段、新语义）不记 journal——它是仓库的版本变化，不是「我经历」的认知事件。事实性增量写进 `map.zh.md`（认知地图）、`learning-path.zh.md`（路线指针）、`index.zh.md`（清单登记）；只有产生了「原以为 X → 实际是 Y」的认知翻转才记 journal。

版本对齐的产出是**打补丁**（增量、surgical），不是重写。补丁以「版本 + 日期」留痕，见 `map.zh.md` 顶部「状态」行。

## 治理姿态：轻治理

- 中文单语；pi 官方文档只有英文，本区不做翻译、不写进 `packages/coding-agent/docs/`。
- `learning/` 不在 `npm run check` 的检查范围（biome 只管 JS/TS/JSON，见根 [package.json](../package.json) 的 check 脚本）；三条纪律作为约定自愿遵守：相对链接有效、一段一物理行、文件以恰好一个换行符结尾。
- 文件名用英文 slug + `.zh.md` 后缀。

## 目录结构

| 位置 | 内容 | 命名与规则 |
|---|---|---|
| [index.zh.md](index.zh.md) | 本区文件入口索引与进度看板 | 固定名 |
| [learning-path.zh.md](learning-path.zh.md) | 学习路线：读什么、按什么顺序（七阶段 + 入门锚点） | 固定名 |
| `plan/` | 各阶段的执行路线与逐步勾选进度（把 learning-path 某阶段拆成可推进的小步骤） | `stage-N.zh.md`（`N` 为阶段号）；只拆解、不复述 learning-path，冲突以 learning-path 为准 |
| `experiments/` | 动手实验：假设 → 操作 → 观察 → 结论，会被笔记引用 | `NNN-slug.zh.md` 编号前缀，日期写在文内；编号一旦被引用不再改动，重做实验新开编号 |
| `journal/` | 认知事件（卡点、突破、误解被修正）的原始记录 | `YYYY-MM-DD-NN-slug.zh.md` 日期 + 当天序号（从 01 递增）；只在事件发生时写，无事不写 |
| `journal/topics/` | 主题聚合索引：把一个理解主题的历次 journal 会话串起来 | `slug.zh.md`；只链不写 |
| `notes/` | 认知单元：一篇 = 一个可独立复述的理解 | `slug.zh.md` |
| `guide/` | 指导性手册：长期反复照做的操作手册（怎么做 vs notes 的怎么理解） | `slug.zh.md`；按需生长，不预铺 |
| `scripts/` | 可跑脚本（动手产出的可执行文件） | 按需生长，不预铺 |
| `design/` | 设计方案 | 按需生长，不预铺 |
| [map.zh.md](map.zh.md) | 认知地图：当前对整体结构的心智模型快照 | 固定名；可推翻的草稿 |
| [questions.zh.md](questions.zh.md) | 开放问题池：三态流转 | 单文件；超过约 50 行或出现 3 个以上域主题时按域拆分，本文件退化为索引 |

**journal 事件驱动**：价值密度在事件不在天数；时序由文件名日期 + 序号前缀兜底。不要为了「每天都写」而写。

**命名不对称是有意的**：experiments 用编号（被 notes 的「验证方式」字段引用，编号是比日期更稳定的引用目标——笔记可以重写多次而引用不断链）；journal 用日期 + 序号（不被任何文件引用，保留时序）。不要「顺手统一」两者。

notes/ 内部按认知类型分桶，按需生长，不预铺空文件：

- `architecture/` — 宏观理解：分层与依赖拓扑的自己的话重述、误解记录。
- `mechanisms/` — 横切机制：agent loop 的继续条件、会话 JSONL 的 append-only + parentId 分支模型、扩展加载序等跨包不变量。
- `modules/` — 具体包：ai / agent / coding-agent 优先，其余按工作触碰的领域生长。

## 记录方式：三层载体

学习过程是自底向上的：先理解局部，归属关系在理解之后才浮现。因此**不要预置目录结构，让结构自己长出来**。三层载体对应三种认知活动，正交、互不重叠：

| 载体 | 回答的问题 | 性质 |
|---|---|---|
| journal | "我经历了什么" | 时间线，只增不改，允许半成品 |
| questions | "我卡在哪、答没答" | 索引，三态流转 |
| map | "我现在整体怎么理解" | 快照，随时可推翻重画 |

### journal 两级组织

- **下级（会话）是唯一事实源**：`journal/YYYY-MM-DD-NN-slug.zh.md` 只增不改，写当下发生了什么、卡在哪、结论是什么；允许半成品与事后被推翻的判断。
- **上级（主题）是纯聚合视图**：`journal/topics/<topic>.zh.md` 不写正文，只做两件事——一句话定位主题；按时间列出指向会话篇的链接 + 每篇一句摘要。
- **不要预铺**：等写了若干篇会话、发现它们其实在讲同一件事，再建主题篇串起来。过早命名主题，会把初始误解固化成错误目录名。

### questions 三态流转

一条问题经历三个状态，每个状态可跨越很长时间：

- **open**：已提出、未解答。
- **analyzing**：分析中，反复推敲、读代码验证。
- **resolved**：已解答，填答案摘要与出处链接，或蒸馏进笔记后删除。

问题的分析过程记在 journal 里；`questions.zh.md` 只维护**当前状态 + 一句话 + 指向详情的链接**，是活的索引，不是仓库。

### map 两级组织

map 是「整体理解慢慢增长」的载体，一个文件装下两种互补投影：

- **一级（结构化提纲，导航面）**：分模块列「已知 / 未知 / 我猜测但未验证」，让人一眼看到整体图景与认知缺口。
- **二级（纯文字 + mermaid，理解面）**：对提纲每个节点展开「我目前怎么理解它」+ 一张局部图，承载因果链。

提纲在上、详解在下，提纲每项锚定下方详解。map 的独特价值在于显式记录「我还不知道什么」——架构理解一半是「知道了什么」，一半是「知道自己卡在哪」。

**图会随时间变多**：当某模块的 mermaid 已画三四张，把它下沉到 `notes/architecture/` 或 `notes/mechanisms/`，map 里只留提纲 + 一句话 + 链接。成熟路径是「map 草稿 → 稳定后迁进 notes → map 原位留链接」。

### 落盘约定：AI 提议，读者裁决

落盘的**决定权在读者（学习者）**，不在 AI：

- 每轮讨论结束后，AI 主动询问「这轮是否需要记录或整理」。
- 读者回答「需要」时，AI 才落盘（journal 会话篇 / questions 登记与状态流转 / map 更新 / notes 迁移）；否则一律不写。
- AI 不自行判断「有没有认知增量」并偷偷落盘——很多讨论只是临时澄清，只有读者知道这轮是否值得沉淀。

讨论是进料、读者是滤网、AI 是执笔：读者只负责理解与提问，不手动整理文件，但保留「记不记」的最终裁决权。

## 笔记模板

modules 笔记模板（其他桶按需裁剪；experiments 与 journal 的形态见各自现有文件）：

```markdown
# <包名/主题> 学习笔记
状态: 草稿 | 已对照验证（YYYY-MM-DD 对照 <事实源文档>）

## 事实源（链接，不复述）
## 它是什么（用自己的话，≤5 句；写不出 = 没懂）
## 关键实体（逐个链接到 home）
## 与相邻单元的关系（依赖谁 / 被谁依赖）
## 我曾经的误解（原以为 → 实际是 → 修正来源）——学习笔记的黄金内容
## 验证方式（指向 experiments/NNN 或一条可复跑命令）
## 遗留问题（登记进 questions.zh.md）
```
