# 安全策略

本文档旨在帮助你理解 Pi 背后的安全概念以及边界在哪里。

总体而言，Pi 是一个在运行它的用户的安全边界内本地运行的编码 agent。用户有责任监控其操作，或将其限制在容器、虚拟机或其他沙箱方案中。

Pi 将本地用户账户和该账户可写的文件视为与 Pi 进程本身相同的信任边界内。如果攻击者可以修改用户主目录、工作区、shell 启动文件、环境或 Pi 配置下的文件，他们通常可以影响 Pi 或其他本地开发工具。依赖此类既有本地写入权限的报告不构成安全漏洞，除非它们展示了 Pi 如何授予该写入权限或跨越了操作系统权限边界。

Pi 依赖用户安装可信任的扩展、加载可信任的技能（skill），并且只在可信任的仓库中使用 pi。这是因为像 `AGENTS.md` 这样的文件或注释中的指令可以轻易地对编码 agent 进行提示注入（prompt injection），而这无法被防护。

## 报告漏洞

如果你认为在 pi 或本仓库中的其他包中发现了安全漏洞，请通过以下方式私下报告：

- 发送邮件到 `security@earendil.com`，或
- 通过本仓库的 GitHub Security Advisories 提交私有报告

请包含：

- 问题描述及其影响
- 复现步骤、概念验证（proof of concept）或相关日志
- 受影响的包、版本、commit 或配置
- 任何已知的缓解措施

不要为安全敏感的报告创建公开 issue。我们会审查报告并酌情协调披露。

## 范围

分发的包、命令行工具、API 和仓库代码中的安全问题在范围内，earendil 在 `pi.dev` 上运营的基础设施也在范围内。

## 范围之外

- 本地代码执行或沙箱行为（Pi 编码 agent 有意不包含沙箱）
- 用户安装的 pi 扩展或技能的行为
- 在不可信仓库中工作的风险
- 安装不可信的扩展、技能、包或工具的风险
- 由不可信 MITM 代理引起的问题
- Pi 安装的公网暴露
- 提示注入攻击
- 属于第三方/用户控制的凭据的暴露秘密
- 需要在目标机器上创建、修改、删除或替换文件、目录、符号链接、环境变量、shell 配置或其他用户控制的本地状态的报告。这包括 `~/.pi`、`~/.pi/agent/models.json`、工作区文件、`AGENTS.md`、技能、扩展、扩展配置、dotfiles，以及通过 NFS、漫游配置文件或 dotfile 管理器同步的文件，除非报告展示了 Pi 本身如何授予该访问权限。
- 由故意弱化的用户配置引起的问题
- 需要受信任的本地输入/配置针对 pi 编码 agent 的资源/DOS 声明
- 关于恶意模型输出的报告
- 将用户批准或用户发起的本地操作当作漏洞的报告

## 给报告者的说明

最有用的报告展示当前可复现的安全边界绕过及其已证实的影响。只展示预期的本地 agent 行为、提示注入或恶意的受信任扩展/技能的报告在此模型下不构成安全漏洞。

例如，一份报告显示写入受信任的 Pi 配置文件的恶意内容导致 Pi 执行命令、加载攻击者控制的工具、将凭据发送到攻击者控制的端点或以其他方式改变行为，这属于范围之外。

可能的情况下，请包含确切的影响路径、包版本或 commit SHA、配置，以及针对最新 release 或最新 `main` 的概念验证。对于依赖报告，请提供证据表明所发布的依赖受影响且该问题可通过 Pi 触达。对于暴露秘密的报告，请提供证据表明该凭据属于 Earendil 或授予对 Earendil 运营的基础设施或服务的访问权限。
