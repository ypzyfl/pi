## 模型目录机制（deepseek-v4.1-flash 缺失）

- pi 的模型目录不是实时拉取，而是 **models.dev 的生成快照**：`models.dev/api.json` --generate-models.ts--> `packages/ai/src/providers/data/<provider>.json` --> `providers/<provider>.models.ts` --> `models.generated.ts`。AGENTS.md 红线：不可手改生成物。
- 实测（2026-09-14）models.dev 官方 `deepseek` provider 仅 4 个：deepseek-v4-flash、deepseek-v4-flash-vision-exp、deepseek-v4-pro、deepseek-flash（本地快照只有前 3 个，落后）。
- `deepseek-v4.1-flash` **不在官方 deepseek provider**，只被第三方收录（openrouter/opencode-go/vercel/nano-gpt/ollama-cloud/greenpt 等）。所以 `npm run generate:models` 也刷不出来。
- 解法：`~/.pi/agent/models.json` 给 deepseek provider 加 `models` 数组（内置模型保留、按 id upsert），或换用已收录的第三方 provider。
- 用户本机 `~/.pi/agent/settings.json`：defaultProvider=deepseek、defaultModel=deepseek-v4-pro、defaultThinkingLevel=high。模型默认值持久化机制：`/model` 回车=会话级；`/model` + Ctrl+S=写全局 settings 作为启动默认。

## modes 与 AgentSession 层次（architecture.zh.md §4）

- 用户问：interactive/rpc/print 是否由 AgentSession 组装？→ **不是，方向相反**。
- 事实（main.ts: 930-974 / 111-122、interactive-mode.ts: 520）：`resolveAppMode()` 依 --mode 与 stdin/stdout 是否 TTY 选模式；main.ts 先 `createAgentSessionRuntime()` 建 runtime（含 services+session），再把同一 runtime 传给 `runRpcMode` / `new InteractiveMode(runtime)` / `runPrintMode`。三种 mode **接收** runtime，不创建 AgentSession。
- 层次：cli.ts → main.ts（编排）→ modes（入口/宿主，持有 runtime 并驱动）→ AgentSession（组装中枢，组装五个服务）→ 更下层。
- 职责：modes 管"怎么和外界交互"（TUI / stdio JSONL / 一次性输出）；AgentSession 管"agent 怎么工作"。
- 已修正 §4：MODES 节点移入 coding-agent subgraph + 标注"（main.ts 依参数与 TTY 选择）"，边改标"创建 runtime 并驱动会话"；读法新增 modes 层次说明。
